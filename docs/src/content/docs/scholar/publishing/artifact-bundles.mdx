# Share verifiable evaluation evidence

Separate the signed verification attestation from the Console export wrapper and
human-readable publication archive. Each has a different purpose and checksum.

## Export a run view

```bash
curl -H "X-Api-Key: $SERVICE_API_KEY" "http://localhost:5000/api/v1/evidence/packages/RUN_ID?download=true" -o evidence.agentv-package.json
```

The export is a version 2 presentation wrapper containing scenario/manifest views
and the signed typed VerificationPackage. Its export checksum is not the signed
package's canonical commitment. It does not embed the exact raw JSONL bytes
needed for independent authoritative verification.

Export the actual committed trace bytes and execution manifest/scenario through
the run provider's authorized interface, without reconstructing events or
normalizing line endings. Place those files alongside the package:

```bash
agentv verify-package evidence.agentv-package.json --trace run.jsonl --execution-manifest execution_manifest.json --scenario scenario.json --require-scenario --public-key trusted-public.pem
```

The trust key must come from an external trusted source, not merely the package.
Signature-only validation and `--diagnostic` analysis cannot establish execution
or a certified pass. See the [package specification](/spec/agentv_package_spec/)
and [verification workflow](/auditor/verification/).

## Publication archives

Use the [publication suite](/evaluator/advanced-publication-suite/) to conduct,
aggregate and render a campaign. Its bundler requires a loaded ArtifactPlugin:

```bash
python eval_runner/publication_suite/bundle.py results/YOUR_BATCH
```

`YOUR_BATCH` must already exist. The bundler selects available aggregate results,
leaderboard/pilot HTML and manifest files. Inspect the actual archive contents;
do not assume it contains a raw trace, complete current certificate and every
sidecar automatically. There is no `agentv bundle` command.

The archive's evidence manifest/checksums protect its selected contents. To prove
a certification claim, distribute the signed package, raw bytes, actual scenario
and execution manifest with the trusted-key verification instructions above.
`agentv verify --run-id` verifies a provider-owned run, not an arbitrary downloaded
ZIP. Retention requirements need external WORM storage rather than a local ZIP.
