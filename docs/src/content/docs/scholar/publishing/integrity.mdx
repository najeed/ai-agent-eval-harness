# Evidence integrity for research

Publish enough evidence to distinguish execution, evaluation and certification.
A completed conversation, a score or an exported ZIP alone is not a certified
passing result.

## Execute and certify

Run an explicitly configured agent against the actual scenario with the intended
execution mode and required independent observations. Undeclared execution mode
defaults to simulated. A live/hybrid label alone does not prove live state;
certification reconciles actual provenance and required oracle outcomes.

For an eligible completed run with a configured signer:

```bash
agentv certify --run-id RUN_ID
agentv verify --run-id RUN_ID
agentv gate --run-id RUN_ID --verify-ledger
```

The provider atomically commits the certificate and sealed lifecycle. The verdict
and score come from the observed evidence, not caller overrides. Valid negative
attestations must not be presented as passing certification.

## Current signatures

Certificate, typed verification package and evaluator finalization signatures use
[`agentv.signature.digest-envelope.v1`](/spec/digest-signature-envelope/).
The exact unsigned projection, canonical envelope, purpose, external signer/key
policy and strict base64 signature encoding are part of verification. Old raw
hex signatures are not the current artifact contract. The package hash, trace
digest and envelope payload digest are separate commitments.

## Independent verification

Distribute the signed package, exact committed `run.jsonl`, actual execution
manifest, executed scenario and externally trusted public key:

```bash
agentv verify-package evidence.agentv-package.json --trace run.jsonl --execution-manifest execution_manifest.json --scenario scenario.json --require-scenario --public-key trusted-public.pem
```

Success requires the package signature, raw trace, manifest/scenario, evidence
graph, complete oracle inventory and signed finalization to agree. Provider-native
run verification additionally checks sealed lifecycle state. Signature-only or
unsigned diagnostic success is not a complete authority verdict. Report the
actual verification status rather than an obsolete `SIGNATURE_MATCH` label.

Keep signer fingerprints, dataset/model revisions, seeds and environment details
with your research materials so another reviewer can interpret the claim's scope.
