# Seeds and reproducibility

DefaultRunner seeds Python's `random` for attempt k using:

```text
attempt_seed = base_seed + (k - 1)
```

Here k is one-based. For base seed 42, three attempts use 42, 43 and 44. Use
`--seed` and `--attempts` on `agentv run` or `agentv evaluate` to select these
inputs. The offset is a reproducible input convention; it does not prove
statistical independence between attempts.

## Scope of the seed

Provider/model seed support is conditional. DefaultRunner does not universally
seed NumPy, freeze a judge's temperature, set subprocess hash randomization or
control remote model scheduling. Publication conductor separately starts
subprocesses with `PYTHONHASHSEED` and task-index-derived seeds; document which
entry point produced the experiment.

Equal seeds cannot guarantee equal model responses, external service state,
network behavior or cross-machine execution. A low temperature can reduce some
variation, but is not proof of deterministic inference.

## Revisit a failure

Preserve the actual scenario revision, base/attempt seed, target and model
configuration, plugin/provider versions, tool definitions, environment state and
exact trace bytes. Re-run with the same inputs, then compare the new observations
with the original evidence. Differences may reveal service or environment drift;
an identical reasoning trajectory is not promised.

```bash
agentv run --path industries/telecom/scenarios/technical_support/13814_home_internet_slow_speed.json --agent http://localhost:5001/execute_task --seed 42
```

Treat environment fingerprints and provider manifests as evidence about recorded
inputs, not a snapshot that automatically restores every external dependency.
For publication, report versions, settings, repeated-run variation and the
conditions needed to provision the environment alongside the seed.
