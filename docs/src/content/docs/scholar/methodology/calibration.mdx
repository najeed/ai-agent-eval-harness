# Calibrating a judge

Use human-labelled samples to assess a judge before interpreting its scores.
The [calibration utility](/evaluator/calibration/) computes MAE, Pearson
correlation and an F1 threshold sweep from task-ID-aligned event values. It does
not compute a built-in Stability Index or Bayesian aggregation.

## Research protocol

1. Configure the judge provider, model, rubric and supported temperature settings
   explicitly. Lower temperature can reduce variation, but does not guarantee
   deterministic inference. Record model versions and scoring fallback behavior.
2. Repeat scoring on a fixed labelled sample and report the distribution of scores
   and agreement with human labels. Preserve separate measurements: the calibrator
   keeps only the last value per task ID rather than aggregating repeated attempts.
3. Compare judges on the same sample, inspect disagreement cases and validate any
   proposed threshold on held-out data. State sample sizes and uncertainty.

## Consensus and human review

The registered `consensus_scoring` metric provides a lightweight agreement
measure under its metric configuration; it is not an automatic multi-provider
Bayesian inference pipeline. Bayesian aggregation, outlier rejection and routing
judge disagreement into HITL require a separately implemented research workflow.
Report the actual method and review decisions rather than claiming an automatic
stability score or product-generated review path.
